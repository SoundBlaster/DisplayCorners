# Наблюдение hooks — прототип

Небольшой наблюдатель для проверки входа hooks. Он не является адаптером и не подключён к приложению. Принимает JSON hook через stdin и записывает только время, тип события, хеш session_id, notification_type и reason в путь из DISPLAY_CORNERS_TRACE. Prompt, cwd, транскрипт, tool_input и ответы инструментов в запись не входят. Ошибки записи не прерывают harness.

Установка hook не выполняется автоматически. Для подготовки конфигураций укажите новый временный каталог:

```sh
python3 prototypes/hooks/prepare.py /путь/к/новому/каталогу
```

Скрипт создаст `claude/settings.json` и `codex/.codex/hooks.json`. Запуск harness выполняется из соответствующего временного каталога с переменной `DISPLAY_CORNERS_TRACE`, указывающей на отдельный файл журнала. Claude Code можно запустить с `--settings` и этим файлом настроек. Codex загружает project hooks только в доверенном проекте и требует доверия к определению hooks. Подготовка не меняет пользовательские настройки или trust. Не записывайте trace в существующий журнал.

## Наблюдение 24 ноября 2026

На этом Mac в ограниченной тестовой сессии Claude Code 2.1.288 с временной конфигурацией пришли SessionStart, UserPromptSubmit и SessionEnd. После UserPromptSubmit процесс завершился ошибкой обновления OAuth-токена и ответ агента получен не был. Эти события подтверждают вызов наблюдателя, но не выполнение работы агентом. Нельзя по одному UserPromptSubmit делать достоверный вывод, что модель начала работу.

Codex CLI 0.163.0 ответил на короткий запрос в отдельной временной директории, но проектный hook в двух пробах не вызвался. Причина не установлена; документация требует trusted project и доверия к hook. Результат не доказывает, что hooks недоступны в Codex. Ни пользовательская конфигурация, ни доверие к hooks не изменялись.

В этих пробах не проверялись PermissionRequest, принятие или отказ, переход в конкретную сессию, визуальный интерфейс и поведение после возобновления авторизации.

## Предварительные требования к ТЗ

- Рабочее состояние должно подтверждаться событием, которое действительно означает начавшуюся работу. Одного UserPromptSubmit недостаточно.
- Ошибка авторизации и отсутствие событий не должны превращаться в подтверждённую работу или ожидание.
- Восстановление состояния и отображение запроса разрешения нужно проверять на реальных сессиях обеих программ.
- Не принимать и не отклонять разрешение из наблюдательного hook.
- До проверки открытия нужной вкладки или окна сообщать, что переход к сессии не подтверждён.
