# Агентский угол — черновик ТЗ

Этот документ собирает требования для первой реализации по итогам визуального прототипа. Контракт интерфейса и подробные условия остаются в [спецификации SpecPM](agent-corner.spec.yaml), смысл обмена с источниками — в [протоколе адаптера](harness-adapter.md). Прототип показывает макет с тестовыми данными; его одобрение не подтверждает работу функции на настоящем дисплее или с настоящим агентом.

## Что должно получиться

На дисплее с включённой нижней правой программной маской DisplayCorners показывает общий индикатор состояния агентских сессий. При наведении рядом открывается список, из которого можно перейти в выбранную сессию её клиента. В первой версии рассматриваются Codex и Claude Code; SessionMonitor используется только как название проекта в примере, зависимость от него не нужна.

Минимальная версия macOS для приложения с этой функцией — **macOS 26**. Текущий проект пока поддерживает macOS 13; deployment target будет изменён при реализации.

## Интерфейс

- Индикатор — цветная точка, целиком помещённая в чёрной маске. При ожидающем ответе или разрешении она янтарная, при работе без ожидающих запросов — синяя; ожидание имеет приоритет. Когда активных сессий нет, остаётся обычное скругление.
- Область активации прилегает к нижнему правому углу и составляет 2R × 2R, где R — фактический радиус маски. Маленький индикатор не требуется точно наводить.
- Если установлен хотя бы один hook агента и выбранный радиус меньше 24 pt, фактический радиус масок увеличивается до 24 pt. Выбор пользователя сохраняется и снова применяется после удаления всех hooks; увеличение не зависит от того, есть ли сейчас активные сессии. Это значение предстоит проверить визуально на реальном дисплее.
- Меню использует сдержанное полупрозрачное стекло. Для образца R = 24 pt нижний и правый отступы равны 4 pt, радиус нижнего правого угла меню — 20 pt; дуги концентричны. Для других подходящих радиусов используется фактический R.
- Строка содержит название проекта, значок Codex или Claude Code и текст состояния; имя агента доступно для assistive technology. Статус не передаётся только цветом. Обе строки имеют одинаковое действие без стрелки.
- При открытии строки упорядочены от более старого изменения состояния сверху к более свежему снизу. Пока меню открыто, обновление состояния не пересортировывает строки, новые сессии добавляются сверху. При добавлении или удалении строк сессия под указателем остаётся на том же месте; если это невозможно, изменение состава откладывается до безопасного момента.
- Наведение не переводит фокус к агенту. Щелчок по строке запрашивает переход именно к выбранной сессии; ответ на вопрос или разрешение остаётся в исходном клиенте. Если переход недоступен, это должно быть понятно пользователю.
- На каждом подходящем дисплее положение следует его настройкам и изменениям. При отключении маски или нижних углов агентский угол этого дисплея скрывается. Физически скруглённые углы вне текущего объёма.

## Данные

Источники подключаются через общий [контракт адаптера](harness-adapter.spec.yaml). Работа и ожидание показываются только при подтверждении источником; неизвестность и устаревание не означают завершение сессии или ответ пользователя. Применяются простые таймауты, их значения и подтверждение долгой работы предстоит подобрать по результатам проверки harness. Конкретные hooks и доступность перехода определяются отдельно для каждого клиента.

Настройки подключения агентов доступны через существующую точку входа в настройки приложения в менюбаре.

## Проверка первой реализации

1. Две разные сессии одного проекта показываются отдельно, а выбор каждой адресован её источнику и сессии.
2. Наведение в квадрате 2R открывает меню; указатель можно перевести в список, не переводя фокус в приложение агента. Геометрия и внешний вид проверяются на реальном дисплее.
3. Изменение статуса не переставляет строку; добавление и удаление не заменяют строку под указателем. После повторного открытия восстанавливается порядок по времени изменения.
4. При истечении срока актуальности старый статус не выдаётся за текущий. Подтверждённое возобновление работы снимает состояние ожидания.
5. Масштабирование, изменение радиуса и подключение нескольких дисплеев не отделяют меню или индикатор от соответствующей маски. Отключение маски скрывает агентский угол.
6. Иконки имеют подписи для accessibility; русская и английская локализации приложения проверены для новых строк.
7. При слишком маленьком выбранном радиусе установка hook увеличивает фактический радиус, а удаление всех hooks восстанавливает выбранное значение. Проверка не зависит от наличия активной сессии.
8. На mock-сессиях A и B открыть список, обновить A и добавить C. Состояние A меняется на месте, C появляется сверху, координаты A и B не меняются. Если это невозможно, C откладывается до закрытия, но общий индикатор обновляется. Затем удалить B: ожидающая удаления строка не показывает устаревший статус и не открывает другую сессию. При повторном открытии остаются актуальные строки в порядке последних изменений.

## Открытые вопросы до реализации

- Значения таймаутов и представление устаревших данных ещё предстоит определить при реализации.
- Подтверждение реальных статусов, hook-событий и перехода по сессии для каждого harness пока не завершено. Автоматическая проверка hover в визуальном прототипе была безрезультатной.

Quick actions, выдача разрешений из меню и стопка карточек в стиле Notification Center отложены.
