# Codex: первый адаптер через hooks

Статус: проект, до проверки реального запуска. Адаптер следует [общему контракту](harness-adapter.md); SessionMonitor не используется.

## События

- `SessionStart` и `UserPromptSubmit` означают, что сессия наблюдается, но сами по себе не подтверждают работу. Состояние — `unknown`.
- `PostToolUse` означает, что инструмент вернул результат. Это подтверждённая активность; кратковременно показываем `working`, затем при отсутствии новых подтверждений — `unknown`.
- `PermissionRequest` запускается перед разрешением, но другие hooks могут принять решение до показа вопроса. Поэтому в первой версии это `unknown`, а не подтверждённое `waiting_for_user`.
- `Stop` и `Interrupt` убирают активный ход из списка, но не утверждают завершение сессии. `SessionEnd` прекращает наблюдение сессии.

При запуске адаптер не знает о прежних сессиях. Snapshot неполный; переход к конкретной сессии не поддерживается. Таймаут активности первоначально 60 секунд и настраивается для debug; это не доказательство окончания работы. При недоступном получателе событие может потеряться, но hook не должен блокировать Codex или принимать решения о разрешениях.

Пользователь устанавливает и удаляет hooks из настроек Display Corners, доступных в менюбаре. Существующие hooks и остальные настройки Codex сохраняются; доверие установленным hooks пользователь подтверждает штатно в Codex. Приложение не сообщает об успешном доверии только на основании установки. Установленные пути должны переживать перезапуск приложения.

Hook выбирает из входа только `session_id`, `hook_event_name` и имя последнего компонента `cwd`; остальные поля, включая prompt, tool input и transcript, не пересылаются и не сохраняются. Это прототип для локальных сессий, а не утверждение о поддержке всех клиентов или удалённых поверхностей.

События с `agent_id` относятся к subagent: они не обновляют родительскую сессию, даже если Codex передал в них её `session_id`. Наблюдение отдельных subagents в первую версию не входит.

Официальный источник: [Codex hooks](https://developers.openai.com/codex/hooks) (просмотр и доверие через `/hooks`; `PermissionRequest` и `PostToolUse`). Особенности фактически установленной версии и реальные потоки событий проверяются отдельно.

## Проверка

1. Проверить установку и удаление в изолированной конфигурации, содержащей сторонние hooks. Пройти обычный review/trust для временного hook в Codex; постоянные пользовательские настройки не менять автоматически.
2. В изолированной сессии Codex вызвать инструмент. Увидеть в debug-потребителе правильный проект и подтверждённую активность.
3. Подать синтетический `PermissionRequest`, проверить `unknown` без фиктивного разрешения, затем проверить истечение срока состояния и `Stop`.
4. Отключить получатель и убедиться, что hook возвращает управление без решения по разрешению и без передачи содержимого запроса.
