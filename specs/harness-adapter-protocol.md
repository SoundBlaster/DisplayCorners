# Проект протокола адаптера harness

Статус — draft. Адаптер сообщает Display Corners наблюдаемые состояния сессий и, если клиент позволяет, помогает перейти к выбранной сессии. Harness остаётся владельцем сессии и разрешений. SessionMonitor не является зависимостью.

## Состав

Адаптер конкретного harness получает его события, например через hooks, и переводит их в общий формат. Display Corners использует сведения, чтобы показать индикатор и список. Адаптеры Codex и Claude Code нужно проверить отдельно: доступные события и возможности перехода могут отличаться.

Для первого прототипа предлагается локальный Unix socket с JSON-объектами по одной строке. Конкретный способ, которым краткоживущий hook передаёт событие адаптеру, определяется при реализации. Настройка и запуск hooks не входят в протокол обмена с Display Corners.

## Сессия и состояние

Пара source_id и session_id адресует конкретную сессию. Адаптер сообщает название harness и доступные название проекта и имя агента. Если данные неизвестны, они остаются отсутствующими.

Поддерживаются три состояния:

- working — harness подтвердил работу;
- waiting_for_user — harness подтвердил запрос разрешения или ответа;
- unknown — достоверное состояние неизвестно.

Нельзя делать вывод о работе или ожидании только по существованию процесса. Адаптер передаёт потребителю доступные подтверждённые наблюдения в порядке их обработки. Если адаптер не может установить актуальное состояние, он сообщает unknown.

## Обмен

При подключении адаптер сообщает свой source_id, harness и поддержку перехода к сессии. Потребитель запрашивает snapshot, а адаптер возвращает известные сессии и признак complete.

Полный snapshot заменяет список сессий данного источника. Неполный snapshot обновляет известные записи и не означает, что отсутствующие сессии закончились. Адаптер, получающий события только через hooks и не умеющий обнаруживать уже запущенные сессии, сообщает неполный snapshot.

Пока соединение открыто, адаптер отправляет update для новой или изменившейся сессии и remove, когда подтверждённо перестаёт её наблюдать. При разрыве потребитель отмечает сведения источника как неподтверждённые. После подключения запрашивается новый snapshot.

## Актуальность

Подтверждённое состояние имеет ограниченный срок актуальности. После таймаута оно становится неизвестным, а не считается завершённым или обработанным. Проверка связи с адаптером сама по себе не продлевает актуальность состояния. Адаптер может повторно сообщить состояние только когда harness действительно позволяет его подтвердить.

Точные значения таймаутов и способ подтверждения продолжительного ожидания определятся после проверки реальных Codex и Claude Code. Пока нет достоверного подтверждения, длительное ожидание может стать неизвестным.

## Переход к сессии

По нажатию строки потребитель отправляет запрос с source_id и session_id соответствующему адаптеру. Адаптер сообщает, что запрос передан клиенту, что переход подтверждён, либо что переход не поддерживается или недоступен. Таймаут ответа означает неизвестный результат. Переход не отвечает на запрос разрешения.

Способ перехода зависит от клиента и терминала. Если конкретную сессию открыть нельзя, адаптер явно сообщает об этом. Поддержка перехода в Codex и Claude Code ещё не подтверждена.

## Пример

Пример иллюстрирует сообщения, но не утверждает наличие реализации или поддержку конкретных hooks.

```jsonl
{"type":"source","source_id":"claude-local","harness":"Claude Code","can_open_session":false}
{"type":"snapshot_request"}
{"type":"snapshot","complete":false,"sessions":[]}
{"type":"update","session":{"session_id":"session-a","state":"waiting_for_user","project":"DisplayCorners","agent":"Claude Code"}}
{"type":"open_session","source_id":"claude-local","session_id":"session-a"}
{"type":"open_result","result":"unsupported"}
```

Порядок строк открытого меню и поведение указателя определяются спецификацией агентского угла. Проверку событий, таймаутов и переходов проводят на реальных сессиях. При необходимости контракт уточняется по результатам наблюдений.
