# Источники событий для адаптеров Codex и Claude Code

Дата сверки документации — 24 ноября 2026 года. Это исследование интеграции, а не подтверждение работы адаптеров. Display Corners использует собственный контракт адаптеров; SessionMonitor не является зависимостью.

## Сопоставление событий

| Событие | Codex | Claude Code | Применение в Display Corners |
| --- | --- | --- | --- |
| Отправка запроса | UserPromptSubmit | UserPromptSubmit | Само событие не подтверждает, что агент начал работу. |
| Запрос разрешения | PermissionRequest | PermissionRequest | Кандидат на waiting_for_user. Сам hook не принимает решение вместо пользователя. |
| Следующее событие инструмента | PostToolUse | PostToolUse, PostToolUseFailure | Подтверждённая активность после запроса может снять ожидание. Отказ или отмену нужно проверить отдельно. |
| Окончание хода | Stop, Interrupt | Stop, StopFailure | Не считать автоматически завершением сессии. Значение для отображения результата пока отложено. |
| Окончание сессии | SessionEnd | SessionEnd | Убрать сессию из активных при подтверждении. |
| Сетевое разрешение | PermissionRequest включает managed-network approval | Notification с permission_prompt для sandbox network requests | Отдельно проверить отображение ожидания в Claude Code. |

Источники: [Codex hooks](https://developers.openai.com/codex/hooks), [Claude Code hooks reference](https://code.claude.com/docs/en/hooks).

У обоих hook получает session_id и cwd. Адаптер может извлечь из cwd имя проекта, не передавая содержимое prompt и tool_input. Hook сообщает только наблюдаемое событие. Простой срок действия ограничивает устаревшие данные, но его истечение не доказывает завершение хода и не является ответом на запрос разрешения.

## Особенности, которые нужно проверить

- Codex требует review и trust для non-managed hooks. Новые или изменённые определения пропускаются до доверия. Конкретную установленную версию и поверхности CLI, IDE и desktop необходимо проверить отдельно. [Codex hook trust](https://developers.openai.com/codex/hooks)
- Codex SessionEnd может наступить после периода неактивности, а не при переключении с разговора. Один SessionEnd недостаточен для немедленного определения окончания хода. [Codex hooks](https://developers.openai.com/codex/hooks)
- Claude Code запускает Notification с permission_prompt после задержки около шести секунд; быстрый ответ может не породить это уведомление. PermissionRequest не вызывается для sandbox network request. Поэтому покрытие обоих вариантов требует проверки на реальных запросах. [Claude Code PermissionRequest](https://code.claude.com/docs/en/hooks#permissionrequest)
- Codex App Server документирует thread/list и thread/status/changed, включая waitingOnApproval у загруженного thread. Нужно отдельно выяснить, охватывает ли доступное соединение уже запущенные пользовательские сессии, и не считать отдельный app-server наблюдателем всех экземпляров без проверки. [Codex App Server](https://developers.openai.com/codex/app-server)
- Hook session_id сам по себе не доказывает возможность открыть нужную вкладку терминала или окно клиента. При отсутствии подтверждённого способа перехода адаптер сообщает unsupported или unavailable согласно контракту.
- Нужно измерить, какие события приходят после allow, deny, cancel и прерывания у каждого клиента. До этого нельзя обещать немедленное снятие индикатора ожидания.
- Хуки — события, не полноценный снимок уже запущенных сессий. Полноту после старта, перезапуска и потери сообщений придётся подтверждать отдельным механизмом, либо сообщать неполный снимок.

## Проверки перед интеграцией

1. Запустить изолированные тестовые сессии Codex CLI и Claude Code с временной конфигурацией hooks. Записать только тип события, session_id и относительный порядок, без содержимого запросов.
2. Проверить запрос разрешения, подтверждение, отказ, отмену, обычное завершение хода и аварийную остановку.
3. Проверить отдельные поверхности CLI и desktop и восстановление после перезапуска получателя.
4. Проверить возможные переходы к сессии отдельно для каждого клиента и терминала. Явно отметить unsupported там, где нельзя адресовать конкретную сессию.
